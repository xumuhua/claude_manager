# D-FLOW9 阶段五 Step1 摘要：乱序发射 + 回填数据 crossbar 两方向 IR 提案（2026-09-07）

哥哥原话（技术指令忠实传达）：「对于IR wau top，我们继续优化。对于这个模块，其核心性能问题是每个bank会存在模仿仲裁拥塞引入的随机延迟。因此，乱序发射就是这个模块的性能优化核心。充分的乱序发射能力以及数据接受能力，是能够极大的提升性能的。所以你接着这个思路继续思考优化。然后是回填数据，因为我们访问是有特点的，所以是可以做一层crossbar，按照字节选出来对应的bank，然后做循环移位器得到最终的结果，这样面积更小。」

红线遵守：IR 先行——两方向均为提案，**未动任何 IR/RTL**；两提案分开报不捆死。分析基于 sweep4 既有 VCD 与三 case 全量 Python 仿真（1,087,361 beat 全数）。

## 方向一：内部乱序发射 + 完成即回收信用（性能核心）

### 现状量化（VCD 逐拍实测 std）

| 指标 | POOL=16 | POOL=48 | POOL=64 |
|-----:|----:|----:|----:|
| 总拍数 | 5,789 | 3,615 | 3,353 |
| nocredit 发射停拍 | 3,292（56.9%） | 379 | 0 |
| 出线空闲且被序卡（头部阻塞） | 1,416（24.5%） | 875 | 0 |
| 出线空闲且无已齐线（供给受限） | 2,041（35.3%） | 408 | 1,029（30.7%） |
| 拍均在途 beat | 15.28 | 33.93 | 41.61 |

账本闭合：T = 出线必耗 2,332 + 序卡空闲 1,416 + 无齐空闲 2,041 ≈ 5,789 ✓。

### 契约判定（可行性锚点）

**data_out 保序不可让渡**——三重锁定：FS FL_WAU_0203 明文 UOP 序返回 + iface.ir data_per_uop order=in_order + env top_check 顺序核对模型（红线原件）。→ 乱序只能做「内部乱序 + 出口恢复序」。rack 已天然 OOO 不涉。

### 两案

**方案 A（建议先行）：完成即回收信用**。credit 回收点从 data_out 握手拍提前到 cov_any（完成入队 DONE_Q）拍。LB 槽语义缩为「在途」，已齐线排队由 DONE_Q 承接（深度=POOL，已齐上限天然=POOL 无需加深）；出线仍严格按 line_seq 序 → top_check/B7 golden 零改动。量化：63.6% 的 nocredit 拍 pool_full 解除；理论稳态 T≈2,422 拍（POOL/往返=16/10=1.6>1 → 出线 II=1 打满；保守下限 ≈4,373）。
- 安全域：环序窗不变式严格保持（发射仍按序，窗内两两差<LB≤POOL≤64≪128）；inv_credit_loop 等价改写（回收点前移，守恒不变）。

**方案 B（二阶段备选）：完整乱序 ROB**。发射谓词放宽为环序窗内自由乱序（S4 互锁修法直接沿用），出口按环序最小出线。增量收益=消「无齐空闲」——但该间隙受 bank 随机延迟方差主导（p64 nocredit=0 仍有 30.7% 证明），**加 POOL 与乱序发射在此等效**，而 POOL 面积线性。判定：A 落地后若仍有 gap 再议 B 的 ROI。

### 待拍板 ①

## 方向二：回填数据 bank 域旋转落线（写侧 crossbar 重构，面积核心）

### 现状（wau_top.v:1093-1102）

写路径 = 32 lane × 动态 (w_seq%LB, w_slot) 全交叉，每 (行,段) FF 位 32 源写选择树。yosys 面积（POOL=16，area 口径与 S4 area5 可比）：**全设计 1,770,832 cells，MUX 1,581,157 占 89%；lb_raw 写树结构上界 32,768 FF × 31 mux2 = 1,015,808 mux2（占总 MUX 57%）**。
（如实登记：首版 nowrmux 差分仅 -93 cells 系实验设计缺陷——只换数据源保留动态译码且 yosys 把 32 lane 写口吸收进 memwr 抽象——不作数，上界推演为提案口径。）

### 访问规律（三 case 全量验证，1,087,361 beat 无一例外）

- linear（2,034 beat）：bank(slot j) = (bank0+j) mod 32 严格 +1 步进。
- trans rot≠0（1,085,327 beat）：偶组 rail r → (c0+r)、奇组 → (c0+r+1)，奇组 lane ≡ 下一偶组 lane（100%），碰撞对恒 (2r+1, 2r+2)。
- **统一译码式 lane(s) = (k0 + (s>>1) + (s&1)) & 31**（linear 的 (s>>1)+(s&1)=s 恰为恒等折叠，两型同式）——**slot→bank 是转轮带**，印证哥哥判断。

### 方案：bank 域 barrel 旋转 + slot 域列写

bank_data 总线（32×128b）→ **barrel 旋转 by -k0**（5 级 2048b 纯接线级联）→ 旋转后位置 x 的段按随行 slot 列写 lb_raw[row][s*128 +: 128]。
- **存储形态不变**（lb_raw 仍 slot 域 16×2048b）→ 出线 P1/P2 零改动、容量零改动、B7 零改动。
- 写侧账：barrel 10,240 + 列选 2:1×16 段 2,048 ≈ **12.3k mux2 替代上界 1.02M（≈82 倍结构性缩减）**；预期 area 口径 1.77M→≈0.8M cells。
- 冲突论证：同 lane 双占（G120 面）被 env per-bank depth2 FIFO 串行化天然化解。
- k0 发射拍随 chunk_meta 存 5b（linear=base>>4，trans 复用 t_row_main 派生链）。
- 防御回退：规律外激励型（未来扩展）回退「逐 lane 独立段写」模式位，lb_mask 覆盖核对护栏。
