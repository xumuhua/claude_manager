# qa（独立验证专家）经验沉淀

## 标杆打法（2026-08-23 v1.3 验证，7 用例 21 断言全绿）
- 红线程式执行纪律：只测不修、全程零写入（探针均被拒）、验证前后比对 hub_seq 证明零副作用、纪律自查写进报告。
- token 运行时从生产 config 读取，不硬编码、不入库、不出现在报告。
- 主动做超出派发范围的"自选补充抽查"（未登记专家越权、混合订阅）——加分项，值得在派发时明确鼓励。
- 报告即留档：~/qa_v13_report.md 格式（逐用例表：步骤/期望/实际/结论 + 纪律自查 + 观察项与缺陷分级）可作后续 QA 任务模板。
- 观察项与缺陷分开列（如 R5.5 生产未复验仅标注不越权去修）——分寸感好。

## 标杆打法（2026-08-24 guard 两轮复测）
- **突变区分度验证**（值得列为修复类复测标准动作）：复测缺陷修复时，用同一脚本 `--mode mutation` 对修复前备份代码跑一遍——旧代码必须复现缺陷 FAIL、新代码全 PASS，证明测试"不是怎么都过"，有精确区分度。
- 独立构造与 coder 自测同构但带精确断言（预排程快环 8 发踩"跳变必命中单飞"路径），专打开发自测盲区。
- 交付物不同步（deploy 测试副本落后于 git）会如实标注为流程观察项 O 级，不越权自行同步。
- 复测报告格式沿用模板 + 附复现命令行，manager 可一键核验。
