# mp-backend（F5 小程序后端）部署手册

> 当前状态：**开发态**（域名未到位，见 `交互留档/M4_域名与备案跟踪单.md`）。
> 本文区分「开发态自测」（现在即可做）与「正式部署」（**域名到位后**执行替换步骤）。

## 1. 架构位置

```
微信小程序 ──wx.request / WS──► mp-backend（备案域名服务器，本服务）
                                    │ HTTP/WS（内网）
                                    ▼
                                hub（manager 机 :8765，F1 §9 端点）
mp-backend 同时直连 GitHub（api.github.com / raw.githubusercontent.com，匿名、仅 public 仓）。
```

- 本服务**不修改 hub**，仅作为 F1 定义的「小程序后端」端接入（以哥哥 token 身份）。
- 鉴权两层：小程序端 → mp token（本服务强制可见性红线）；mp-backend → hub 哥哥 token。

## 2. 开发态自测（本机）

```bash
cd /data/workspace/expert-intercom/mp-backend
python3 -m venv venv && venv/bin/pip install aiohttp pyyaml   # 首次
nohup venv/bin/python server/app.py --config config.yaml >> logs/mp-backend.log 2>&1 &
curl http://127.0.0.1:8766/healthz
```

- 依赖：Python ≥ 3.10 + aiohttp + pyyaml，零重型依赖（与 hub 同风格）。
- 开发态 token 在 `config.yaml` 明文（测试 token，不得推 GitHub）。
- 自测用例：`venv/bin/python tests/selftest.py`（见 tests/ 内说明）。

## 3. 正式部署（域名到位后，按序执行）

### 3.1 代码与环境

```bash
sudo mkdir -p /opt/expert-intercom && sudo cp -r mp-backend /opt/expert-intercom/
cd /opt/expert-intercom/mp-backend
python3 -m venv venv && venv/bin/pip install aiohttp pyyaml
sudo mkdir -p /var/lib/expert-intercom
```

### 3.2 替换 token（必做）

1. hub 侧：A-arch 在 hub `config.yaml` 登记正式哥哥 token（`endpoint_role: gege`，`scope: [group, dm]`），SIGHUP 热加载；token 经带外通道（微信私聊）下发。
2. mp-backend 侧：`config.yaml` 中 `hub.token` 与 `agents[].token` 全部改为 `env:` 引用；
   真实值写入 systemd override（见 `mp-backend.service` 注释），**任何真实 token 不入库、不进 GitHub**。
3. **AI 中转 key（2026-08-23 新增，D1 v2）**：`ai.ark_key` 走 `env:DOUBAO_ARK_KEY`——
   `source /home/manager/keys/doubao.sh && export DOUBAO_ARK_KEY="$ANTHROPIC_AUTH_TOKEN"`，
   生产写入 systemd override 的 `Environment=`（参照 `run_dev.sh`）。
   语音（ASR/TTS）待哥哥申请 openspeech 独立 appid+token 后设
   `DOUBAO_SPEECH_APPID` / `DOUBAO_SPEECH_TOKEN`；未配置时对应接口降级 `503 AI_UNAVAILABLE`，不影响其余功能。

### 3.3 域名与 SSL（**域名到位后替换**）

1. DNS：备案域名 A 记录指向本服务器；完成 ICP 备案（企业主体，哥哥申请，跟踪见 M4）。
2. 证书：`sudo certbot --nginx -d {{DOMAIN}}`（或手动放置证书）。
3. Nginx：`nginx/mp-backend.conf` 全文替换 `{{DOMAIN}}`、`{{SSL_CERT}}`、`{{SSL_KEY}}` →
   `/etc/nginx/sites-available/mp-backend` → 软链 enabled → `sudo nginx -t && sudo systemctl reload nginx`。
4. 验证：`curl https://{{DOMAIN}}/healthz` 返回 `hub_connected: true`。

### 3.4 systemd 常驻

```bash
sudo cp mp-backend.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now mp-backend
journalctl -u mp-backend -f
```

### 3.5 微信小程序后台配置（企业主体）

- 开发管理 → 服务器域名：`request 合法域名` = `https://{{DOMAIN}}`；`socket 合法域名` = `wss://{{DOMAIN}}`。
- 微信登录（openid）到位后：在 `config.yaml` agents 区填 openid 完成 token ↔ openid 绑定（接口已预留）。

### 3.6 验收

- `https://{{DOMAIN}}/healthz` 正常（合法域名校验通过的前置）。
- 开发者工具关闭「不校验合法域名」后两功能（对话/阅读）实测 —— 即 F5 验收标准第 1 项「合法域名校验通过」。

## 4. 运维速查

| 项 | 位置/命令 |
|----|-----------|
| 日志（systemd） | `journalctl -u mp-backend -f` |
| 日志（nohup 开发态） | `mp-backend/logs/mp-backend.log` |
| last_seq 持久化 | `--state` 指定文件（默认 mp-backend/last_seq.state），进程重启不回退 |
| hub 断连 | 自动按 5s→10s→30s→60s 退避重连，恢复后自动补发；`healthz` 可看 `hub_connected` |
| 端口 | 8766（WS 与 HTTP 同端口） |
